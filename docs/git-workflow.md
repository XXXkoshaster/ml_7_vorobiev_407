# GitHub Flow

Каждый этап начинается в отдельной ветке от актуальной `main`. В `main` не коммитим напрямую: туда попадают только изменения, которые прошли ревью.

1. Создаём ветку этапа от `main`, выполняем работу и фиксируем её коммитами. Обновляем `todo.md`, `state.md` и `journal.md` в той же ветке.
2. Перед слиянием проверяем diff относительно `main` и запускаем проверки по объёму изменений. Для ноутбуков проверяем запуск с чистого ядра, пояснения к кодовым ячейкам и полученные результаты. Кратко записываем, что проверено и какие замечания остались.
3. Если подключён GitHub, открываем pull request в `main`: в описании указываем цель, проверки и ограничения. Для каждой операции с удалённым репозиторием заранее получаем явное разрешение пользователя. Пока удалённого репозитория нет, показываем локальный diff или его сводку и результаты самопроверки. Самопроверка не заменяет одобрение ревьюера.
4. Исправляем блокирующие замечания. Сливаем только после одобрения ревьюером, а без GitHub — после подтверждения пользователя. После слияния следующий этап начинаем от обновлённой `main`.

| Этап | Ветка |
|---|---|
| План и правила работы | `docs/project-plan` |
| Подготовка данных и протокол оценки | `feat/data-setup` |
| Каркас проекта и инструкция запуска | `feat/project-setup` |
| Лабораторные 1–5 | `feat/lab-01-knn`, `feat/lab-02-regressions`, `feat/lab-03-tree`, `feat/lab-04-forest`, `feat/lab-05-boosting` |
| Итоговый ноутбук | `feat/summary` |
| Финальная проверка и правки перед сдачей | `chore/final-check` |
