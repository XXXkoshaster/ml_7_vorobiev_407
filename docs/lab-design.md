# Разбор ТЗ и структура репозитория

Нужны пять ноутбуков лабораторных и шестой, отдельный, для сравнения. В каждой лабораторной решаем две задачи на одном и том же наборе данных для каждой задачи. Пункт «регрессии классификации» трактуем как задачу регрессии: далее ТЗ явно требует модели и для классификации, и для регрессии, а ЛР2–5 повторяют пункты 2–4, но не выбор начальных условий.

## Предлагаемая структура

```text
ml/
├── README.md              # задачи, источники данных, установка, порядок запуска
├── requirements.txt       # numpy, pandas, scikit-learn, matplotlib, jupyterlab
├── .gitignore             # окружение, кеши, контрольные точки Jupyter
├── notebooks/
│   ├── 01_knn.ipynb
│   ├── 02_regressions.ipynb
│   ├── 03_decision_tree.ipynb
│   ├── 04_random_forest.ipynb
│   ├── 05_gradient_boosting.ipynb
│   └── 06_summary.ipynb
├── data/                  # исходные CSV, если разрешено хранить в GitHub
├── results/               # lab01.csv … lab05.csv для итогового ноутбука
├── docs/                  # разбор ТЗ и описание структуры
├── state.md
├── journal.md
└── todo.md
```

Собственные модели оставляем в соответствующих ноутбуках, чтобы на защите формулы, код и результаты были рядом. Не добавляем пакет `src/`, CI или трекер экспериментов. Если данные нельзя включить в репозиторий, в `README.md` указываем источник, точное имя файла и куда его положить. Если наборы небольшие и лицензия разрешает, храним их в Git вместе с CSV результатов. Указываем единый рабочий каталог запуска, чтобы относительные пути не зависели от догадок.

## Данные и метрики

| Задача | Датасет | Практическая постановка |
|---|---|---|
| Бинарная классификация | [Spambase (UCI)](https://archive.ics.uci.edu/dataset/94/spambase) | Фильтрация входящих писем по частотам слов и символов и статистикам заглавных букв. Цель — последний столбец `spambase.data`: `1` — спам, `0` — не спам. |
| Регрессия | [SML2010 (UCI)](https://archive.ics.uci.edu/dataset/274/sml2010) | Прогноз температуры в столовой умного дома, чтобы заранее реагировать на её изменение. Для ЛР1 предлагаем предсказывать температуру через 15 минут по измерениям, доступным к моменту прогноза. Горизонт и набор признаков уточнить по исходным файлам. |

Эти датасеты используем во всех пяти лабораторных. Уникальность обоих наборов в группе пока не подтверждена. Для Spambase UCI указывает CC BY 4.0: при публикации указать авторов и источник. Условия публикации SML2010 ещё нужно сверить.
- Классификация: основной кандидат — **F1-macro**, чтобы каждый класс имел одинаковый вес; дополнительно — **accuracy**, чтобы показать общую долю верных ответов. Утвердить метрики после просмотра баланса классов и описать, почему они подходят выбранной задаче.
- Регрессия: **MAE** как основная метрика в единицах целевой величины и **RMSE** как дополнительная, чувствительная к большим ошибкам. Утвердить после выбора задачи.
- Spambase: стратифицированное разбиение 80/20 с фиксированным `random_state` и стратифицированная кросс-валидация на обучающей части. SML2010: разбиение и кросс-валидация по времени, без перемешивания; обучающие цели должны предшествовать началу следующей части. Один и тот же тест для каждой задачи во всех пяти лабораторных; не использовать его для выбора гипотез и параметров.

## Шаблон каждой лабораторной

1. **Базовый sklearn.** Обучить классификатор и регрессор с базовыми параметрами и с минимальной обработкой, нужной для запуска. Записать метрики.
2. **Улучшенный sklearn.** Сформулировать 1–2 проверяемые гипотезы на модель и задачу, показать результаты, включая неподтвердившиеся. Для подбора достаточно небольшой сетки и трёх фолдов на обучающей части. Обработку, которая учится по данным, включить в `Pipeline`, чтобы она обучалась отдельно на каждом фолде. Выбрать конфигурацию по основной CV-метрике, переобучить на всей обучающей части, оценить на тесте и сравнить с пунктом 1. Если проверенные изменения не дали выигрыша, так и указать.
3. **Базовая и улучшенная собственные модели.** Написать `fit`/`predict` без готовых обучаемых оценщиков sklearn в ядре; использовать NumPy и при необходимости общие инструменты sklearn для разбиения, метрик и препроцессинга. Базовую сравнить с базовой sklearn, улучшенную — с улучшенной sklearn. Перенести выбранные техники, насколько позволяют реализованные параметры; заранее выбирать гипотезы, которые можно перенести. Объяснить остаточные различия, а не требовать совпадения метрик до последнего знака.
4. **Выводы и экспорт.** Показать изменения основных метрик на одинаковом тесте, объяснить, что помогло и где результат ограничен. Записать 8 строк в CSV: 2 задачи × 4 варианта. Единые столбцы: `lab,task,algorithm,variant,f1_macro,accuracy,mae,rmse`; неприменимые метрики оставить пустыми.

У каждой кодовой ячейки, в том числе в итоговом ноутбуке, перед кодом должна быть Markdown-ячейка с пояснением назначения входов, действий или результата. Она должна объяснять смысл шага, а не пересказывать синтаксис.

## Что реализовать своими руками

| ЛР | Классификация | Регрессия | Примеры гипотез |
|---|---|---|---|
| 1. KNN | Голосование соседей | Среднее по соседям | Масштабирование, выбор `k` |
| 2. Регрессии | Логистическая регрессия: сигмоида и градиентный спуск | Линейная регрессия: метод наименьших квадратов через `np.linalg.lstsq` | Масштабирование для логистической; полиномиальные признаки для линейной |
| 3. Дерево | Бинарные разбиения по критерию Джини, класс большинства в листе | Разбиения по снижению квадратичной ошибки, среднее в листе | Ограничение глубины и минимального размера листа |
| 4. Лес | Бутстрэп-выборки, случайное подмножество признаков в каждом узле, усреднение долей классов из листьев | Те же принципы, среднее по предсказаниям деревьев | Число деревьев и `max_features` |
| 5. Бустинг | Начальный логит по доле класса; деревья регрессии учатся на `y − p`, предсказание через сигмоиду | Начальный прогноз — среднее; деревья регрессии учатся на остатках `y − ŷ` | Скорость обучения, число и глубина деревьев |

Лес и бустинг используют ядро дерева из ЛР3. Когда оно понадобится второй раз, вынести его в один модуль `notebooks/tree.py` и импортировать в ЛР3–5. Собственный классификатор бустинга — упрощённый вариант градиентного спуска в пространстве функций: шаги к sklearn сравниваем по качеству, а отличие, например обновление значений листьев, описываем отдельно. Для sklearn берём `KNeighborsClassifier/Regressor`, `LogisticRegression` и `LinearRegression`, `DecisionTreeClassifier/Regressor`, `RandomForestClassifier/Regressor`, `GradientBoostingClassifier/Regressor`.

## Итоговый ноутбук

`06_summary.ipynb` читает пять CSV, не переобучая модели. Показывает две таблицы — по классификации и регрессии — по 20 строк на задачу, с сортировкой по основной метрике. Отдельно отмечает, где улучшения помогли и насколько собственные реализации близки к sklearn. Качество классификации и регрессии между собой не сравниваем. Для сдачи выполняем все ноутбуки сверху вниз из чистых ядер и сохраняем результаты в репозитории.
